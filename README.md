# 七巧板１０００题练习

一个面向家庭练习的七巧板静态网页，内置１０００道图案，支持自由练习、限时模拟比赛和进阶拼图。采用原生 HTML、CSS、JavaScript 与 SVG，无后端、账号或第三方 CDN，运行时无需安装依赖或构建。

自由练习和模拟比赛中的板块朝向预先摆好，玩家只需拖动到目标位置。进阶拼图会打乱部分板块的方向。三个模式都是放对后吸附锁定，放错回到原位。界面以手机竖屏为主，也适配较宽和较矮的视口。

## 开始使用

直接用浏览器打开 [index.html](index.html) ，启用 JavaScript 即可练习。浏览器需要支持 SVG、Pointer Events 和原生 `dialog`，保存进度还依赖本地存储；尚未完成各浏览器与真机兼容性验收。

也可以在仓库根目录启动本地静态服务，本机已有 Python 时执行：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

然后打开 [本地练习页面](http://127.0.0.1:8000) 。无需安装 npm 包。

## 练习规则

| 项目 | 自由练习 | 模拟比赛 | 进阶拼图 |
| --- | --- | --- | --- |
| 题目 | 全部１０００题，按四类浏览，每页１２题 | 从全题库随机抽取７道不重复题目 | 全部１０００题，按四类浏览 |
| 时间 | 不限时 | 整场共５分钟 | 不限时 |
| 提示 | 默认只显示轮廓，可切换分块线，换题后恢复隐藏 | 始终只显示轮廓 | 拖动时高亮匹配的目标位，可手动显示分块线 |
| 切题 | 分类选题、上一题、下一题 | 答题卡、上一题、下一题 | 分类选题、上一题、下一题 |
| 提交 | 检查当前题完成情况 | 确认后交整卷，到时自动交卷 | 检查当前题完成情况 |

三个模式均以七块全部放对为一道题完成。

比赛交卷后显示完成题数和用时，可以逐题检查已提交的摆放状态，不能继续修改本场答案。

进阶拼图中，点一下板块会顺时针转４５°。点棋盘右下角的「翻面」，平行四边形会沿一条固定的长边收起，再从另一侧展开。再点一次会翻回。系统启用「减少动态效果」时，翻面会直接切换。板块锁定后，翻面按钮不可用。棋盘右上角的「显示分块线」可打开提示，换题后恢复隐藏。拖到匹配的位置会高亮，松手即吸附。点底部「提交」可检查当前题完成情况。

选题界面的分类会结合题库分组和少量显示名称修正，当前分布如下：

| 分类 | 题数 |
| --- | --- |
| 基础图形 | １３５ |
| 动物 | ３１５ |
| 人物 | １７７ |
| 生活物品 | ３７３ |
| 合计 | １０００ |

## 进度保存

页面通过 `localStorage` 保存当前一份自由练习或比赛会话，存储键为 `tangram-school-web-v1-session`。返回首页后可继续。新开自由练习或比赛会替换当前会话，已有练习摆放或未交卷比赛时会提示确认。

进阶拼图单独保存当前题、摆放状态和板块方向，存储键为 `tangram-school-web-v1-challenge`。点首页的「继续进阶拼图」可恢复，切换到其他模式时会保留该进度。

更换域名、端口、浏览器或设备不会自动迁移记录，本地文件地址的进度也不会自动带到静态站点。浏览器禁止存储时页面会提示，当前页面仍可练习，关闭后无法保留进度。

比赛按开始时记录的绝对截止时间计时。返回首页、进入进阶拼图、刷新、切到后台或关闭页面均不暂停计时。如果在挑战中到期，系统会自动交卷，可以回首页查看比赛结果。

## 目录与实现

```text
tangram/
├── index.html                  # 首页、拼图页、成绩页和弹窗结构
├── app.css                     # 页面样式与视口适配
├── app.js                      # 页面切换、选题、拖动、提交与存档
├── engine.js                   # 板块布局、形状匹配、吸附、计时和恢复校验
├── puzzles.js                  # 生成后的浏览器题库，含合并轮廓路径
├── source/
│   ├── library-1000.json        # 题库数据源：坐标、分类和逐题来源
│   ├── build-puzzles.mjs        # 题库生成脚本
│   └── upstream/               # GLPeces 上游源码归档及来源哈希
├── licenses/                   # 随包保留的第三方许可文本
├── .nojekyll                   # GitHub Pages 静态文件配置
├── CREDITS.md                  # 来源及许可范围
├── CLAUDE.md                   # 项目维护约定
└── ROADMAP.md                  # 当前进度、待办、阻塞与验证记录
```

页面依次加载 `puzzles.js`、`engine.js`、`app.js`。引擎根据题目坐标计算 SVG 布局，拖动结束时按形状和距离寻找未占用的兼容目标位；已放好的板块锁定。题目轮廓预先由七块多边形求并集生成，避免直接叠画时出现接缝。

## 题库维护

日常运行只使用现成的 `puzzles.js`。仅在修改题库时，编辑 [题库数据源](source/library-1000.json) ，保留稳定 ID、七块坐标和逐题来源，再重新生成浏览器数据。

生成脚本要求本机命令行可调用 `node` 和 `python`，Python 环境提供 Shapely ２.x 所需的 `set_precision` 等 API。脚本当前断言题目数必须为１０００；改变题量时需要同步核对生成断言、页面文案和选题逻辑。

```powershell
node source/build-puzzles.mjs
```

脚本读取源 JSON，用 Python／Shapely 生成目标轮廓，然后覆盖 `puzzles.js`。执行前检查工作区，避免覆盖未保存的手工改动；执行后核对生成差异、题目数量、ID、来源字段与拼图行为。不要直接修改生成文件来维护题库。

## 验证

基础语法检查可在仓库根目录执行：

```powershell
node --check app.js
node --check engine.js
node --check puzzles.js
node --check source/build-puzzles.mjs
```

仓库尚未提供持久化自动测试脚本。引擎可以在 Node.js 中加载后检查布局、吸附、会话创建和恢复；页面变更还需要在浏览器中验证拖动、分类分页、手动交卷、超时恢复和移动端显示。最近一次检查的范围与未验证项见 [进度文档](ROADMAP.md) 。

需要托管时，可将本目录文件放在 GitHub 仓库根目录，在 Settings → Pages 选择 Deploy from a branch、`main`、`/ (root)`。需要保留 `licenses/`、`source/` 和 `.nojekyll`，不要只上传压缩包。
